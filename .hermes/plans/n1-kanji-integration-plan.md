# N1 真题汉字词表融合方案

## 目标
把《快收藏！1200个N1真题汉字汇总》的“词条 → 假名”资料，融合为 `new-N1` 的独立、可练习、可追踪的“真题汉字”模块；不把原始 PDF 文案直接塞进现有页面。

## 已核实的输入
- 原 PDF：`/Users/ayong/.hermes/cache/documents/doc_7d58db896d2c_快收藏！1200个N1真题汉字汇总.pdf`
- 已提取文本：`/Users/ayong/docs/learning/N1_真题汉字_1200_提取.txt`
- 文本为 UTF-8，712 行；开头含发布者、页码和标题等非词条元数据。
- 词条主格式：`汉字词→假名`。例如：`一致→いっち`、`必要→ひつよう`、`期限→きげん`。
- 项目目录：`/Users/ayong/services/new-N1`。

## 设计原则
1. **资料层与学习层分离**：保留原提取文本作为来源，不在前端直接依赖它；运行一个可复现的清洗脚本生成版本化 JSON。
2. **先练后看**：默认遮住读音；用户先判断/输入，再显示假名和结果。
3. **真题来源不能被夸大**：UI 标示为“整理资料中的真题汉字汇总”，而非声称每条均可溯源到某年某套 JLPT 真题。
4. **不凭猜测补词义或音调**：本次只纳入已提供的“词形—读音”事实。中文释义、例句、词性、JLPT 年份标签作为后续可审计扩展。
5. **离线优先**：静态 JSON + 浏览器 localStorage，无账号、无后端依赖。

## 建议模块
### 1. 词库浏览（参考模式）
- 搜索：汉字词、假名双向检索。
- 按首字、词长、是否已掌握过滤。
- 读音默认可点击展开；支持单条标记“认识 / 不熟”。

### 2. 今日复习（学习模式）
- 首次按 20 词/组进入；新词与“困难词”混合。
- 卡片正面：汉字词；背面：假名、（后续才有的）释义/例句。
- 三档反馈：认识、模糊、不认识；决定下次复习优先级。
- 本版采用本地简化间隔：不认识=当天重练，模糊=次日，认识=3/7/14 天；记录算法和版本以便日后替换为 FSRS。

### 3. 小测（检验模式）
- **看汉字选读音**：从同一首字/近似假名中抽 4 个干扰项。
- **看假名选词**：反向识别。
- 先做 20 题小测，结束给出错题清单；错题一键加入困难词。
- 避免“输入法拼写”作为首版硬门槛，减少日语输入法摩擦；后续可加输入模式。

### 4. 进度
- 总词数、已学习、掌握、困难、今日完成数。
- 不报告虚假的“掌握率”：只显示基于用户自评和答题结果的本地统计，并可重置/导出。

## 数据管线
1. 新建 `data/raw/n1-kanji-1200-source.txt`，只复制已提取的 UTF-8 文本，并在文件头记录 PDF 名称与提取日期。
2. 新建 `scripts/build-kanji-dataset.(js|py)`：
   - 仅接受包含且只包含一个 `→` 的行；左右两侧 trim。
   - 过滤水印、`第 N 页 共 8 页`、标题、空行等非词条。
   - 规范化 Unicode 空格、全半角变体。
   - 按 `(term, reading)` 精确去重；相同词形但读音不同保留并在审计报告标记。
   - 为每条生成稳定 ID（基于 term+reading），不可用数组序号作 ID。
3. 输出：
   - `data/n1-kanji.json`：前端消费的结构化词库。
   - `data/n1-kanji-audit.json`：总行数、接受数、丢弃原因、重复项、同形异读项。
4. 人工抽检：开头/中段/末尾各抽 20 条，和原 PDF 对照；人工处理疑似 OCR/提取错行后才发布。

### 建议 JSON schema
```json
{
  "datasetVersion": "2026-08-06",
  "source": {"title": "1200个N1真题汉字汇总", "claim": "第三方整理资料"},
  "items": [
    {"id": "k_...", "term": "一致", "reading": "いっち", "sourcePage": 1}
  ]
}
```
`sourcePage` 仅在可从提取文本可靠恢复时写入；否则省略，绝不编造。

## 实施步骤
1. 只读审计 `new-N1` 当前前端入口、路由、构建方式、测试体系和现有数据加载模式。
2. 落地数据管线和审计报告；先写数据清洗单测（标题过滤、有效词条、重复、同形异读、异常箭头）。
3. 生成数据集并核对：词数不预设为“1200”，以审计报告真实有效数为准。
4. 按既有 UI 架构加入“真题汉字”入口和模块页/路由；实现浏览、学习、小测、进度。
5. 加 localStorage 数据版本迁移：数据集版本改变时保留已有学习记录能匹配的稳定 ID，无法匹配的给出重置/备份提示。
6. 添加前端测试：数据加载、随机题目不把正确项重复放进干扰项、统计计算、localStorage 迁移。
7. 全量构建/测试；本地启动后验证页面、搜索、20题小测、刷新后的学习记录恢复。

## 验证标准
- 数据审计输出可复现，且所有进入词库的条目都符合 `term→reading` 格式。
- 测试全绿；构建成功。
- UI 不暴露读音直到用户主动翻面/作答。
- 刷新浏览器后已学习、困难词、测验统计仍存在。
- 资料来源与“真题”口径在界面中准确，不暗示官方题库或逐题可追溯来源。

## 风险与后续
- PDF 中可能有重复、提取换行和水印；用审计报告与人工抽样阻止脏数据进入学习库。
- 单纯“汉字→读音”无法支持高质量语义辨析；下一期接入可核验日语词典释义、例句和音频，但需记录词典来源/许可证。
- 若现有 `new-N1` 是纯静态项目，首版应继续纯静态；不为此引入数据库或用户登录。
